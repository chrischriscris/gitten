Settings in its own window

Zed opens settings as a separate window (cx.open_window, crates/settings_ui/src/settings_ui.rs:845) — own traffic lights, own title, centered. This study takes that literally for gitten: , opens a "gitten — Settings" window with search, a section sidebar and one-line descriptions per row. A window with no keymap would be a mouse surface, so the window carries its own minimal key context (below) instead of borrowing the main window's mode stack.

Specimen: filter state

Search narrows rows across every section; sections with no match dim out of the sidebar instead of disappearing, so position stays stable while typing. Values apply live to the shared Host and persist to gitten.toml — there is no save button, and the main window re-renders from the same state. File-only config (custom [keys]) gets the Zed fallback: a button, not a dead row.

The window's own keys

The main window's mode stack doesn't reach across windows, so this window defines a fixed, tiny context — not the full keymap, which would be a second keymap to maintain. The search field is a native field; everything else is six bindings. Closing returns focus to the main window.

What was taken, what was left

Takenfrom Zed

Separate window with own chrome; search-first sidebar; one-line descriptions; the file fallback as a first-class row; deep-linkable sections, so a bad value in the TOML can open the window at the offending row.

Leftin-window overlay

The old centered overlay goes away entirely — two settings surfaces would split the keymap question instead of answering it. One surface, one key context, in its own window.

Open decisions

Unchanged — the study assumes these, doesn't settle them.

1. Destructive confirms need a modal answer. Double-press arming works for keys but is undiscoverable and has no mouse path — a destructive pick from the context menu has nowhere to confirm to. Either bless double-press inside menu picks too, or admit a small confirm kind.
2. Pilot the plumbing on the commit editor. Single-line input is fine for branch names; a real commit editor wants multiline. Whichever modal seam wins proves itself there.
3. Share plumbing for the extension seam, not the look. Rule 1: if extensions will ever show a panel, they need a supported container. A second window is a second container to expose — the seam must cover windows, not just overlays.
