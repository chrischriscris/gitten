Visual Blueprint & Layout Anatomy

gitten's desktop presentation adopts a quiet, dense, keyboard-driven layout inspired by lazygit. Every region has a strict geometric rhythm, fixed-height rows for virtualization, and explicit contrast floors.

1. The 3-Pane Geometry

The window is partitioned into three vertical columns using a CSS Grid layout: grid-template-columns: 245px 420px 1fr;.

Pane Key Default Width Content & Behavior
Files / Status 1 245px Staged (M, A) & unstaged (M, ??) files. Subsections for Branches (2) and Stashes (3).
Commits 4 420px Commit topology graph + short SHA + commit subject + relative age. Fixed 22px row rhythm.
Diff Viewer 5 1fr (Flexible) Hunk header, line-number gutters, added/removed lines, intraline word diffs, and docked AI explanation card.

2. Window Chrome & Titlebar Strip

Following macOS titlebar conventions without an opaque system bar: the app window uses a single transparent strip of height 38px.

  • Traffic Lights: macOS window controls inset at (10, 10). Muted dark circles at rest, colored on hover.
  • Repository Path: Breadcrumb showing working directory ~/src/ in dim tone and repo name plait / gitten in bold foreground.
  • Branch Pill: Compact container displaying current active branch with ahead/behind sync counts (↑2 ↓0).
  • Extensions Chip: Active status indicator with green pulse dot showing loaded extensions.
  • Command Keycap: Dedicated ⌘K ask button opening the AI and command dispatch palette.

3. The Commit Graph Drawing Rules

The commit graph is drawn using SVG Bézier curves and antialiased nodes adhering to core/src/graph.rs: 

ROW_H = 22.0 px;
LANE_W = 14.0 px;
STROKE = 2.0 px;
DOT_R = 4.0 px (commit node);
MERGE_R = 5.0 px (hollow merge ring);
lane_x = lane * 14.0 + 7.0 px; // Centered exactly at whole pixels

Merge curves use cubic Bézier curves (d="M 21 22 C 21 16 7 17 7 11") ensuring tangent continuity across row boundaries so virtualized row recycling doesn't produce visual seams.

4. Docked AI Assist Card ("Reading this hunk")

Rather than a noisy pop-up or a separate chat sidebar, AI reasoning is docked directly inside the diff view right below the relevant hunk.

  • Typeface: Editorial serif (Newsreader, Charter, Georgia) at 13.5px with 1.5 line-height to distinguish human/machine prose from monospace code.
  • Border: Muted amber border (rgba(223, 168, 81, 0.28)) creating subtle warm elevation.
  • Interactive shortcut: Pressing e triggers or collapses the hunk explanation.

5. Terminal Variant (gitten-tui) — same core, cells not pixels

Toggle Terminal (TUI) in the mockup toolbar to see the same repository through tui/src/main.rs + tui/src/panes.rs. Same themes, same lane hues, same keymap — drawn into a cell grid (screen::Screen) instead of GPUI elements. Try the --ascii, wide ≥96 and ? keys buttons above the terminal frame.

  • Chrome: one title row (gitten  <pane>  <label> + right-aligned ? keys hint) and one status row (<pane> · <where>). No traffic lights, no pills, no shadows.
  • Layout: sidebar (32% of the body, ≥40 cols) + 1 blank divider column + main (≥55). Below WIDE_AT = 96 the focused pane takes the whole body. Sidebar lists stack vertically with equal slices — files, branches, commits, stashes — each with its own <key> <name> <label> header; the focused header draws in accent.
  • Graph: 2 columns per lane with box drawing (● ◉ │ ─ ┼ ╮ ╯), capped at 12 lanes. --ascii swaps to * @ | - + / \ (Glyphs::ascii).
  • Scrollbar: ▐ drawn over the pane's last cell (row background runs underneath), halves ▝ ▗, # in ASCII. No track, no drag — an indicator only.
  • No AI card: the terminal shows the same hunk and answers the same e on the status line. Mouse: click moves the cursor, drag selects, OSC 52 copies.
